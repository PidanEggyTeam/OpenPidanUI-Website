## 1. 准备

- 确认 `main` 上的构建是绿的；
- 手动跑一遍受影响的皮肤与设置程序；
- 想好版本号（语义化：`0.1.0`、`0.1.1`、`0.2.0`）。

## 2. 打包资产

组件的发布资产是 **`.rmskin`**（皮肤安装包）与可选的 **`.zip`**（便携版设置程序）。

```powershell
# 皮肤打包：Rainmeter 自带 SkinInstaller
& "$env:ProgramFiles\Rainmeter\SkinInstaller.exe" /in OpenPidanUI.rmskin /out dist\OpenPidanUI-<version>.rmskin
```

命名规则：`OpenPidanUI-<组件名>-<version>.rmskin`。**文件名里带版本号**，本站下载页直接把文件名展示给用户。

## 3. 打 tag 与发布

```powershell
git tag -a v0.1.0 -m "v0.1.0"
git push origin v0.1.0
```

到 GitHub 仓库 New release → 选刚推的 tag → 上传资产 → 写更新说明 → 发布。

更新说明建议结构：

```markdown
## 新增
- …

## 修复
- …

## 注意
- 升级前请先卸载旧版皮肤，避免残留旧变量。
```

## 4. 本站怎么跟上

本站**没有后台**。版本信息是在**构建时**从 GitHub Releases API 拉取、归一化后写进静态 JSON 的：

```
GitHub Releases  →  server/routes/api/releases.json.ts（构建期）  →  /api/releases.json  →  下载页
```

所以发版之后需要**重新构建并部署一次本站**。拉取失败（限流、断网、5xx）时，构建会退回到仓库里的
`shared/data/releases.snapshot.json`，页面顶部会显示「快照」提示——不会因为 GitHub 抖一下就发不出去。

:::note
仓库还没有 Release 时，下载页展示的是占位快照。第一次正式发版后，这次快照会被真实数据替换。
:::
